# Telegram-бот для знакомств

Самостоятельный Python-проект. Бот и веб-админка работают в Docker, данные —
в PostgreSQL. Telegram API доступен через существующий Cloudflare Worker из
соседнего репозитория `telegram-api-proxy`; менять или деплоить Worker для
этого обновления не требуется.

## Что умеет первая версия

- Регистрация в личном чате: подтверждение 18+, парень / девушка, возраст
  18–100, одно фото, описание до 500 символов. Имя берётся из Telegram.
- Несколько целей: отношения / свидание, друзья, компания, проект, интересы.
- Предпросмотр и сохранение анкеты. Черновик каждого шага сохраняется в БД
  и восстанавливается через `/start` после перезапуска.
- Просмотр активных чужих анкет, у которых есть хотя бы одна общая цель.
  Свою анкету, скрытые анкеты и уже оценённые карточки бот не показывает.
- Лайк или пропуск. При взаимном лайке оба получают контакт; последние
  50 совпадений доступны через `/matches`. Если уведомление не доставлено,
  совпадение остаётся в базе и в этом списке.
- Редактирование, скрытие / включение показа, удаление с подтверждением.
  Изменения заменяют старую анкету только после сохранения. Удаление
  убирает анкету из бота и удаляет связанные лайки / пропуски; содержимое
  анкеты и текущего черновика сохраняется в закрытом архиве администратора.
- Админка: список, поиск по имени / username / Telegram ID, фильтры по статусу,
  пагинация, карточки с фото и целями, архив всех удалений, блокировка /
  разблокировка пользователя с обязательной причиной и историей действий.

Пока нет геопоиска, фильтра по полу или возрасту партнёра, чата внутри бота,
предварительного одобрения анкет, жалоб, нескольких фото и проверки реального возраста. Совпадение
целей «интересы» не означает совпадение конкретных хобби: отдельных тегов пока нет.
18+ и правила взаимных лайков приняты как исходные настройки первой версии.

## Фото

Пользователь отправляет фотографию боту. В PostgreSQL хранится Telegram
`file_id`, а не файл и не публичная ссылка. Фото остаётся на серверах Telegram;
это не хранение на телефоне пользователя. Для показа в боте повторно используется
`file_id`, привязанный к этому боту. При смене бота старые идентификаторы не следует
считать переносимыми.

В админке браузер обращается к защищённому маршруту `/profiles/ID/photo`.
Сервер вызывает `getFile` и скачивает фото через тот же авторизованный Worker,
передавая его браузеру из памяти (не более 10 МБ). На диск фото не сохраняется;
токен бота, секрет прокси и Telegram URL не отправляются браузеру.
При удалении `file_id` остаётся в архивной копии; фото доступно администратору
через защищённый маршрут `/archive/ID/photo`. Доступность файла по-прежнему
зависит от Telegram. Удаление не стирает сообщения или файлы из Telegram.

## Запуск на сервере

Нужны Docker Engine и Docker Compose v2.

```bash
cp -n .env.example .env
nano .env
chmod 600 .env
docker compose up -d --build
docker compose logs --tail=100 -f bot admin
```

Переменные `.env`:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather |
| `TELEGRAM_API_BASE` | HTTPS-адрес существующего Worker без пути |
| `TELEGRAM_PROXY_SECRET` | Значение `PROXY_SECRET` в Cloudflare |
| `POSTGRES_DB` / `POSTGRES_USER` | По умолчанию `dating` |
| `POSTGRES_PASSWORD` | Отдельный случайный пароль БД |
| `ADMIN_USER` | По умолчанию `admin` |
| `ADMIN_PASSWORD` | Отдельный случайный пароль, минимум 16 символов |
| `ADMIN_BIND` / `ADMIN_PORT` | По умолчанию `127.0.0.1` и `8080` |

Для генерации пароля: `openssl rand -hex 32`. В текущий локальный `.env`
уже добавлены отдельные случайные пароли БД и админки; существующие настройки
Telegram сохранены. При переносе можно безопасно скопировать этот `.env`
или заполнить новый. Секреты не входят в Git, образ или контекст сборки.

Compose запускает `db`, `bot`, `admin`. PostgreSQL не публикует порт на хост,
данные находятся в именованном томе `postgres_data`. Бот и админка ждут
готовности БД; таблицы создаются автоматически с блокировкой параллельной
инициализации. Приложения работают без root, с read-only filesystem и
ротацией логов. Перезапуск контейнеров автоматический; Docker на сервере
должен быть включён в автозагрузку.

Перед запуском остановите старую версию бота с тем же токеном.
Один токен — один polling-процесс. Установленный webhook нужно удалить
перед polling; приложение не удаляет его автоматически.

## Как открыть админку

На том же компьютере: **http://127.0.0.1:8080**. Браузер спросит логин и пароль
из `ADMIN_USER` / `ADMIN_PASSWORD`. Это HTTP Basic Auth, а не секретный URL.
В этой версии нет пользователей админки, ролей и формы выхода: для окончания
сеанса закройте приватное окно браузера. После 10 неудачных запросов с одного
адреса доступ ограничивается на минуту; счётчик хранится в памяти процесса.

Для сервера проще оставить `ADMIN_BIND=127.0.0.1` и с компьютера открыть туннель:

```bash
ssh -N -L 18080:127.0.0.1:8080 user@SERVER_IP
```

Затем откройте **http://127.0.0.1:18080**. Пароль и данные идут через SSH;
публичный порт админки открывать не нужно.

Для доступа по внешнему домену поставьте HTTPS reverse proxy на том же сервере
перед `127.0.0.1:8080`. Например, при установленном Caddy и настроенном DNS:

```caddyfile
admin.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Замените домен своим; HTTPS-сертификат и порты 80/443 обслуживает Caddy.
Не открывайте Basic Auth наружу по обычному HTTP. При reverse proxy лимит
попыток общий для его IP; реальные клиентские заголовки намеренно не доверяются.

## Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Меню или продолжение черновика |
| `/profile` | Моя сохранённая анкета |
| `/edit` | Заполнить заново; старая анкета сохранится до подтверждения |
| `/cancel` | Отменить черновик |
| `/browse` | Следующая подходящая анкета |
| `/matches` | Последние взаимные лайки |
| `/hide` / `/show` | Скрыть / включить показ |
| `/delete` | Удаление с подтверждением |

Цели не являются фильтром пола: парень или девушка — характеристика своей
анкеты. Контакт после совпадения использует стабильный Telegram ID, поэтому
смена username не перенаправляет к другому человеку. Доступность профиля
зависит от настроек приватности Telegram. Текст и фото пользовательской
анкеты могут сами содержать контакты; бот их автоматически не удаляет.

## Архив удалённых анкет и модерация

В верхнем меню админки появился **«Архив удалённых»** (`/archive`). Каждое
удаление сохраняет отдельный неизменяемый снимок: Telegram ID, username,
имя, пол, возраст, описание, цели, `file_id`, даты и текущий черновик, если он
был. Если сохранённой анкеты ещё нет, сохраняется незавершённый черновик.
Повторная регистрация и новое удаление создают новую запись; старые остаются.
Повторное нажатие удаления без новой анкеты не создаёт дубль.
Отмена черновика через `/cancel` и перезапуск заполнения через `/edit` сами
по себе не создают архивные записи: архив фиксирует подтверждённое удаление.

Архив не виден участникам и не участвует в поиске и совпадениях. Копирование
в архив и удаление текущей анкеты выполняются одной транзакцией: если архив
не сохранился, исходная анкета тоже не удалится. Автоматической очистки архива
нет. Пользователь предупреждён о сохранении копии при регистрации и перед
подтверждением удаления. Ранее удалённые старой версией анкеты восстановить
из текущей базы невозможно; миграция сохраняет только имеющиеся данные.

В текущей или архивной карточке есть блок **«Модерация пользователя»**:

- «Заблокировать пользователя»: обязательная причина, 1–500 символов.
- «Разблокировать пользователя»: обязательная причина снятия блокировки.
- Журнал: действие, причина, имя администратора и время UTC. Интерфейс
  показывает последние 50 действий, база хранит всю историю.

Блокировка привязана к Telegram ID и сохраняется после удаления, создания
и изменения анкеты. Заблокированный пользователь не может просматривать
анкеты, ставить лайки или получать контакты через совпадения; его анкета
также исключена из этих выдач. Он может исправить или удалить свою анкету,
но `/show` и повторная регистрация не снимают блокировку. Причина видна
пользователю при попытке поиска или просмотре своей анкеты; отдельная
рассылка уведомлений при действии модератора не выполняется.
Разблокировка сохраняет пользовательский выбор скрыть анкету и не
восстанавливает удалённую. Уже отправленные сообщения Telegram не стираются.

Модерация выполняется POST-запросами с авторизацией и подписанным CSRF-токеном
формы, действующим один час. После перезапуска админки или истечения срока
обновите страницу перед отправкой. Изменение БД и запись в журнал атомарны.

Для обновления работающего сервера сначала перенесите новый код, затем
в папке проекта выполните (том PostgreSQL сохраняется):

```bash
docker compose stop bot admin
docker compose up -d --build
docker compose logs --tail=100 bot admin
```

Миграция применится автоматически. Оба приложения нужно обновить вместе:
старая версия бота продолжает удалять анкеты без архива и не знает блокировок.
Перед обновлением можно сделать резервную копию по инструкции ниже.

## Обновления и резервное копирование

```bash
docker compose up -d --build      # применить код и .env
docker compose ps
docker compose down              # остановить, сохранив данные
```

**Не используйте `docker compose down -v`, если хотите сохранить анкеты.**
Пароль PostgreSQL применяется образом при создании тома; его изменение
в `.env` не меняет пароль уже существующего пользователя БД.

Резервная копия (содержит персональные данные):

```bash
umask 077
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

Восстановление в пустую БД с остановленными приложениями:

```bash
docker compose stop bot admin
docker compose exec -T db sh -c 'psql -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" "$POSTGRES_DB"' < backup.sql
docker compose up -d bot admin
```

Не храните резервные копии в Git. Архив удалённых анкет и история модерации также входят в резервную копию.

## Локальная разработка и проверки

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
docker compose config --quiet
```

Интеграционные тесты создают **отдельный временный PostgreSQL** и удаляют его
после проверки; рабочая БД не используется. Для них нужны `initdb` и `pg_ctl`
в PATH либо `TEST_POSTGRES_BIN=/path/to/postgresql/bin`. Без этих утилит
интеграционные тесты пропускаются. На этом компьютере автоматически используется
установленный PostgreSQL 15 из Homebrew; Compose настроен на PostgreSQL 17.

Для запуска без Docker нужен доступный PostgreSQL. Укажите его параметры в
`.env` и запустите отдельно `python bot.py` и `python -m app.admin`.
Админка без Docker слушает `127.0.0.1:8080`. В Compose адрес БД и внутренний
интерфейс админки задаются автоматически.

`app/db.py` содержит стартовую схему и версионированные миграции.
Применённые версии записываются в `schema_migrations`; миграция архива и
модерации имеет версию 2. Миграции выполняются в транзакции под общей
блокировкой, поэтому одновременный старт бота и админки безопасен. В первой версии один polling-процесс обрабатывает
обновления последовательно; для большой нагрузки это нужно пересмотреть.

Источники: [Telegram file_id и getFile](https://core.telegram.org/bots/api#getfile),
[свой API-сервер в aiogram](https://docs.aiogram.dev/en/latest/api/session/custom_server.html).
